## Verification

- **Real Safari hasn't run anything.** Playwright's WebKit passes the sweep and the behavior checks, but it's a patched build on Windows. Still unseen in Safari: the slider fill (see below), the search clear-button restyle, `closedby`, anchoring, and variable-font weights (Playwright's Windows WebKit draws every weight thin). Mac Mini pass. (a11y pass)
- **The slider has no fill in WebKit.** WebKit accepts the view timeline on the thumb but never runs it, so the track shows no fill; `--_on` keeps it plain instead of a stub. The value is still in the readout. Check real Safari; if it's the same there, a fill needs script or a different technique. (a11y pass)
- **WebKit doesn't focus buttons on click.** Safari behaves the same, so after a mouse click a dialog returns focus to the body, not the opener. The behavior tests open overlays by keyboard for that reason. It's platform behavior, not ours to fix. (a11y pass)
- **Forced colors is only proven in Firefox.** Playwright's WebKit matches `(forced-colors: active)` without applying system colors, and Safari has no forced-colors mode. Chrome is covered by the harness. (a11y pass)
- **Firefox has no search clear button.** It never shows one for `type="search"`, so the restyle only applies in Chromium and WebKit. (a11y pass)
- **The axe sweep isn't in CI.** `ctl.ts axe` runs on demand. Storybook's Vitest addon would run the same `parameters.a11y` checks in CI, but it only sees each story's final state, so open overlays would need `play` functions, and its support for the HTML framework is unconfirmed (storybookjs/storybook#34647). Deferred. (a11y pass)
- **axe can't see contrast over gradients.** Every story on a gradient page reports a `REVIEW` item. The page-background test in `bun test` covers that math; a person still has to look at anything axe flags for another reason. (a11y pass)
- **Popovers without anchor positioning are unobserved.** Firefox and Playwright's WebKit both anchor and flip natively, so the centered-in-viewport fallback has never rendered. (step 2)
- **Sheets under RTL and touch.** `data-side="start|end"` under `dir="rtl"` and `interestfor` on touch (long-press) are unverified. (step 2)
- **Unobserved paths.** These are written but not proven: the slider fill under `:dir(rtl)` and the restyled search clear button (it only shows while hovered or focused with a value). (step 1)

## Behaviors (src/js)

Real Safari may not. The `interestfor` fallback is proven: it runs in Firefox and WebKit, where the tooltip and hover-card tests pass. (step 3)

Every shipped palette got headroom so page text passes on every chrome's page background: light-mode links, danger, borders, and rings got darker (up to 0.11 lightness), dark-mode borders and danger lighter (up to 0.12), and a few chromas dropped where the new lightness is out of sRGB (calm-storm's dark danger, 0.24 to 0.16). default, aurora, and sorbet now override `--danger`. Review the look. (a11y pass)
- **Under `prefers-contrast: more` and forced colors, the page background is flat.** That replaced the scanline switch-off, so those users also lose the subtle page gradients. (a11y pass)
- **Review the ported palettes' repairs.** Contrast repair changed some looks from uvs-decks-gg. calm-storm's light primary went from L 0.746 to 0.536, and white text on danger in dark mode became dark text in all five (uvs-decks-gg kept `#fff` as an owner exception). - **Expressive's uppercase and tracking wrap tight rows.** In the sample app, a card header ("Rotating soon" plus "55 cards") wraps to two lines. Holoterminal does the same. It's a layout pressure to design for, not a component bug. (step 4)
- **Darkmatter is close to calm.** It differs in radii, flatter shadows, and a flat page background. Check it still earns its place as a separate chrome. (step 4)

## Design debt

- **`focusgroup` seam.** All arrow-key movement goes through `src/js/roving.ts`. When `focusgroup` is in more than Chromium and its role and tab-order bugs are fixed, hand the work to the browser there. (step 3)
- **`color-mix(in oklch)` can walk the hue wheel.** The tints and the alert icon moved to `oklab` for this reason. `odd-button` hover still mixes `--_bg` and `--_fg` in oklch. Audit every remaining oklch mix of two different hues. (step 1)
- **Bar fills are not contrast-tested against their rail.** For example, the light-mode warning fill on `--track` is low contrast. The rule is "always show the value as text," and nothing enforces it. (step 1)
- **Slider hover ring is clipped at the far ends.** This is a side effect of `overflow: hidden`, which the fill technique needs. It's cosmetic. (step 1)
- **`odd-segmented` has no disabled styling.** `fieldset disabled` stops its radios, but no rule in `choice.css` dims it, so a disabled segmented control looks enabled. (React Choice)
- **A bare `input.odd-switch` with `disabled` does not dim.** The only dim rule is `.odd-choice:has(:disabled)`, so a switch outside an `odd-choice` label looks enabled while disabled. The Showcase Matrix switch (`stories/Showcase.stories.ts:141`) is one. It is not `disabled` today, but a `disabled` attribute on it would not dim it. (React Choice)
- **A computed `tone` warns.** `<Badge tone={toneOf[status]}>` gives the `ODD-STATIC-001` warning, the same as `<Button variant={v}>`, though `BadgeTone` already guards the value. Trusting typed wrapper props in the ESLint lowering is a change for every part, not only Badge. (React Badge)
- **An empty badge passes every checker.** `<span class="odd-badge"></span>` shows only a colored dot, and no rule reports it. A rule that a badge has text needs a new rule kind. (React Badge)
- **Flat children break the alert layout.** `.odd-alert` is a flex row, and every direct child other than `svg` becomes a column. `<AlertTitle>` followed by bare text renders the text beside the title. In Firefox the text starts at x=145 beside a title at x=8. With a body `div`, the text sits below the title. No checker reports it, because no rule kind reads an element's children. The docs and the stories show the body `div`. (React Alert)
- **Nothing checks that the live region came first.** A later alert is announced only when it lands in a `role="status"` or `role="alert"` container that was already on the page. No rule reads an element's ancestors or when it was inserted, so no checker reports an alert inserted with its container or with no container at all. `ODD-ALERT-003` only forbids `role` and `aria-live` on the alert itself. (React Alert)
- **A misspelled `data-` name on the title reports nothing.** `<p class="odd-alert-title" data-tnoe="info">` and `<AlertTitle data-tnoe="info">` pass every checker, while the same typo on `odd-alert` reports `ODD-ALERT-004` with "Did you mean data-tone?". The near-miss lookup in `systemDataFindings` (`src/js/usage/check.ts`) compares only against the part's own `data-` names, and the title has none, so it has no candidate. Suggesting names from other parts changes the checker for every part. (React Alert)
- **Bare initials pass every checker.** `<span class="odd-avatar">AR</span>` and `<Avatar>AR</Avatar>` are read as the letters A R, with no name. `ODD-AVATAR-004` fires only for `role="img"` on an avatar or `role="group"` on a group, so initials with neither a role nor `aria-hidden` pass. A rule that visible text in an avatar needs `role="img"` or `aria-hidden="true"` needs a rule kind that reads text children, like the empty-badge rule. An image avatar's `img` with no `alt` is not checked either, because no rule reads a child element's attributes. axe reports that one. (React Avatar)
- **A name rule can read another class's role.** `isSet` in `src/js/usage/check.ts` checks the rules of every class on the element, so `<input class="odd-switch odd-avatar" type="checkbox" role="switch">` also reports `ODD-AVATAR-004`. The element already reports `ODD-AVATAR-001` and `ODD-AVATAR-003`, so the extra code is noise on markup that is wrong anyway. Scoping `isSet` to the rule's own class would remove it. Button's `data-icon-only` check has scanned every class the same way since the usage contract shipped. (React Avatar)
- **A vertical separator outside a row passes every checker.** `separator.css` stretches a vertical separator with `align-self: stretch`, so it needs a flex row such as `odd-row`. Elsewhere it is a 1em stub. No rule kind reads an element's parent, so no checker reports it. (React Separator)
- **A Radix separator with the `odd-separator` class reports `ODD-SEPARATOR-002`.** Radix renders `data-orientation` beside `aria-orientation`, and the separator forbids `data-orientation` because `separator.css` does not read it. The line still draws correctly from `aria-orientation`. Nothing in this repo composes Radix onto `odd-` classes today. (React Separator)
- **`Contract` does not type an `enum` attribute outside the row's `props`.** `Avatar` hand-types `role`, and `Separator` hand-types `aria-orientation` and `role`, as `Values<Rule, "attribute">`. Without that line the prop falls back to React's type, so `<Separator role="none">` would type-check. `Contract` in `src/react/part.ts` could derive these lines from the part's `enum` rules. (React Separator)
- **Nothing checks the skeleton's region.** A skeleton block with no `aria-busy` region and no loading text beside it passes every checker, and a screen reader hears nothing while the page loads. No rule kind reads an element's parent. (React Skeleton)
- **A missing required attribute prints "Property missing".** `<Skeleton />` without `aria-hidden`, `Switch` without `type` or `role`, and `AvatarGroup` without `role` give TypeScript's missing property error, not the code. `Pinned` in `src/react/part.ts` could print the code for all three at once. (React Skeleton)
- **A spread silences `ODD-SKELETON-003`.** `required-attribute` skips a node with a spread (`hasUnknownAttributes` in `src/js/usage/check.ts`), so `<Skeleton {...props} />` gives only the `ODD-STATIC-001` warning, whether or not `props` holds `aria-hidden`. `Switch` has the same gap. (React Skeleton)
- **A scene can pass children to a skeleton block.** Scene children follow the `div` tag in `stories/mirror.ts`, not the part's props, so a mirrored story can put text inside `Skeleton` with no type error. `checkRoot` still reports the visible text as `ODD-SKELETON-004`. (React Skeleton)
- **The avatar skeleton matches only the default avatar size.** `skeleton.css` draws `data-shape="avatar"` at the default avatar's `2.5rem`, so a placeholder for an `sm` or `lg` avatar is the wrong size, and `data-size` on the block reports `ODD-SKELETON-005`. Skeleton sizes for `sm` and `lg` would be a CSS change. (React Skeleton)
- **A computed `shape` warns.** `<Skeleton shape={shapeOf[kind]}>` gives the `ODD-STATIC-001` warning, the same as a computed `tone` on `Badge`, though the type already guards the value. (React Skeleton)
- **The omit list in `ODD-SKELETON-002` reads "text and line and rect and rectangular and rounded".** The shared `and` helper in `src/js/usage/format.ts` joins every omit token with " and ", which reads fine for two tokens and badly for five. A list join with commas and a final "and" would fix every enum message at once. (React Skeleton)
- **Nothing checks a card link outside any card.** No adapter passes an element's parent, so `<a class="odd-card-link" href="/decks/ember">` with no card around it reports nothing. Without `href` it reports only `ODD-CARD-005`, which reads the link itself. The static-card half of `ODD-CARD-003` covers a card link inside a card that is not interactive. (React Card)
- **An `<a>` wrapped around a card and a skipped heading level pass every checker.** `<a href><article class="odd-card">` makes the whole card one link whose name is every word in it, and an `h4` title under an `h2` skips a level. Neither shows on the card node. (React Card)
- **A spread or a computed child silences part of `ODD-CARD-003`.** The checker cannot see inside `{...props}` or `<DeckTitle />`, so a missing card link stays quiet. A spread on a card without `data-interactive` hides whether the card is static, so a card link in it stays quiet too. A second control, a link or button that is not the card link, and a card link in a literal static card still report. (React Card)
- **A nested card whose class is computed does not stop the walk.** `descendants` in `src/js/usage/check.ts` stops only at a literal `odd-card`, so the link in `<article className={cardClass} data-interactive>` inside a card counts for the outer card, which reports `ODD-CARD-003`. (React Card)
- **The runtime observer watches insertions only.** Toggling `interactive` on a mounted card does not recheck `ODD-CARD-003`. (React Card)
- **`ODD-CARD-004` also bans click delegation on the card.** A list that handles clicks on each card through `onClick` gets the code. `onClickCapture` still works. (React Card)
- **Showcase sets `--gap` on cards that do not read it.** `card.css` lays the card out with `gap: var(--space-3)`, so `style="--gap: …"` on the two Showcase cards does nothing. Showcase is not mirrored, so the port leaves it. (React Card)

React cannot write it. `open={false}` leaves the attribute off, `open={true}` writes `open=""`, a string `open` is a type error, and React writes a string as `open=""` before the runtime checker reads it. A value check on `open` that skips computed values would catch the raw form without warning on `open={state}`, but it needs a new mode on the shared `enum` kind. (React Disclosure)
